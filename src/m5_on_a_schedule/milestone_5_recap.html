4 · What you learned

Five things

  1. A clock cannot say "after".Cron starts a job on time. Only a dependency makes one step wait for another.
  2. An orchestrator holds no business logic.Each task starts a step of a program that also runs without it.
  3. Use the logical date, never the clock.Then a retry four hours late and a backfill three weeks late both load the right day.
  4. Retry what time can fix. Stop for what only a person can fix.An API that is down comes back. A row with a bad status does not fix itself.
  5. A scheduler is only as safe as your steps are idempotent.Retries, backfills and replays all run a step more than once.

5 · New words

Words you can now explain

Schedule and cronA schedule starts a run at a time. Cron's five fields are the usual way to write one.
OrchestrationRunning the steps in the right order, at the right time, and watching them.
Task and dependencyOne step of the job. A rule that one task needs another to finish first.
DAGDirected acyclic graph: the tasks and the arrows between them.
Data interval and logical dateThe slice of time a run covers. The day a run is for.
TriggerStarting a run by hand, for a day you name.
RetryRunning a failed task again after a wait.
CatchupA scheduler running missed days by itself. Off here.
BackfillRunning the job for a range of past days.
ReplayRunning a finished day again.

Every word of all five milestones has an interview line in the project's glossary.

Set up

What is new to run: Airflow, in Docker

Nothing new to install by hand. One Docker Compose profile starts the warehouse, the order system and Airflow 3.4. The first build downloads about 3 GB and takes several minutes. Give Docker at least 4 GB of memory.

On any system, from the project folder

docker compose --profile schedule up -d --build   # the warehouse, the order system, Airflow
# Airflow's page: http://localhost:8080   (no password)

Stop any order system you started in a terminal first: it now runs in Docker, on the same port 8010.

docker compose exec airflow airflow dags unpause daily_orders
docker compose exec airflow airflow backfill create --dag-id daily_orders \
    --from-date 2026-06-07 --to-date 2026-06-12 --max-active-runs 1
docker compose exec airflow airflow dags list-runs daily_orders

cd src/m5_on_a_schedule
uv run python -m daily_orders report     # the manager's report
uv run pytest                            # several minutes: it drives the real Airflow

To stop everything: docker compose --profile schedule down.
