4 · What you learned

Five things

  1. Do not stop the repeats. Make the write not care.Delivery is at-least-once. An idempotent write turns it into an exactly-once result.
  2. Check the key before you merge.A wrong key overwrites other rows with no error. And a batch must hold each key once.
  3. Prove idempotency with a test.Run the same morning twice, then five times, and compare every row.
  4. A lookback is only safe with an idempotent write.It re-reads rows on purpose. Choose its length from how late your data really arrives.
  5. A query cannot see a row that is gone.Deletes need the source's own list of changes. Keep the row, and mark it.

5 · New words

Words you can now explain

Upsert and MERGEUpdate the row if the key exists, add it if not. MERGE is the SQL statement for it.
OverwriteEmpty the table and load everything. Right for a full load only.
Primary key and natural keyThe column the database keeps unique. A key that comes from the business itself.
Dedupe keyThe key you keep one row per, when a thing arrived more than once.
Idempotent, safe re-runTwo runs leave the same result as one run.
At-most-once, at-least-once, exactly-onceA row can be lost. A row can repeat. Each row changes the result one time.
Late rowA row that reaches the source after the window that should have caught it.
LookbackThe window starts N days before the watermark.
PartitionOne slice of a table. Here, one business day.
ReprocessingBuilding a past slice again, to correct it.
Hard delete and soft deleteRemove the row for good. Or keep the row and mark it.
Log-based CDCCapturing changes from the database's own log. It sees deletes.

Each word has an interview line in the project's glossary.

Set up

Nothing new to install

This milestone uses what milestone 2 set up: Docker for the warehouse, and uv. MERGE needs Postgres 15 or later; the project runs Postgres 16.

On any system, from the project folder

docker compose up -d warehouse       # starts Postgres on port 5440
uv run python -m order_system        # starts the order system; leave it running

In a second terminal:

uv run python -m order_system.clock --morning 2026-06-08
cd src/m3_safe_to_run_twice
uv run python -m daily_orders        # the first load
uv run python -m order_system.clock --advance-days 1
uv run python -m daily_orders        # only what changed
uv run python -m daily_orders        # again: nothing changes
uv run python -m daily_orders --rebuild-day 2026-06-05
uv run pytest                        # this milestone's tests

Every number on this page is written by daily_orders/flow_data.py from a real run of this milestone's code, and a test checks that they still match. All data is fictional. Arden does not exist.
