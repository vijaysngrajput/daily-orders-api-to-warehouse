4 · What you learned

Five things

  1. Load raw first, transform in the warehouse.Then a wrong rule is a rebuild, not a new call to the source.
  2. Clean once, in staging. Then shape. Then add up.Every model after staging can trust: real types, one spelling, one row per order.
  3. Count rows before and after every join.An inner join can drop a city. A join to items can multiply your money by four.
  4. Test the tables, not only the code.A table test is a query for rows that break a rule. It runs on this morning's real data.
  5. An old right number beats a new wrong one.A failed test must stop the report, and say which rule broke.

5 · New words

Words you can now explain

ELTLoad the raw data, then transform it inside the warehouse.
ModelOne SELECT in a file. dbt builds a table or a view from it.
Type casting and cleaningGive each value its real type, and one spelling.
DeduplicationKeep one row per key: the newest.
Join and enrichmentPut two tables side by side where a key matches. Add columns from another table.
Row-by-row and set-basedVisit one row at a time. Or say what you want from all the rows together.
Staging, core, martThree layers: clean it, one row per real thing, what people read.
Incremental modelA model that rebuilds only part of its table.
Table testA query that returns the rows that break a rule. No rows means a pass.
FreshnessIs the newest loaded row recent enough?

Set up

What is new to install: nothing by hand

dbt is new in this milestone. uv sync installs it into the project's virtual environment: dbt-core 1.12 with the Postgres adapter 1.11. Docker still runs the warehouse.

On any system, from the project folder

uv sync                              # installs dbt
docker compose up -d warehouse       # starts Postgres on port 5440
uv run python -m order_system        # starts the order system; leave it running

In a second terminal:

uv run python -m order_system.clock --morning 2026-06-08
cd src/m4_models_and_tests
uv run python -m daily_orders                 # extract, load, then dbt build
uv run python -m daily_orders --freshness     # is the raw data recent?
uv run python -m daily_orders --full-refresh  # rebuild every day of the report
uv run pytest                                 # takes over a minute: it runs dbt many times

To use dbt directly, as an analyst would:

cd dbt_project
uv run dbt build --profiles-dir .
uv run dbt test --select orders --profiles-dir .
