4 · What you learned

Five things

  1. A pipeline is the whole chain, run again and again.One query is not a pipeline. Extract, transform, load and report each have one job, so each can be tested alone.
  2. Say which day, on which clock.Business numbers use event time, in the business time zone. A wrong number with no error is worse than a crash.
  3. Say what one row means before you add anything up.That is the grain. Adding up at the wrong grain counts things twice.
  4. Yesterday's orders are not the same today.A refund three days after delivery lowered an old day's number. A pipeline must load what changed, not only what is new.
  5. Work the answer out by hand first.An answer key lets you check every later version. Without one, you cannot tell a right number from a wrong one.

5 · New words

Words you can now explain

Data pipelineIt moves data from where it is made to where it is used. It works in steps, and it runs on a schedule.
Source and destinationWhere the data is made, and where it is used. Here: the order system, and the warehouse.
Full loadIt reads every row on every run.
Event timeWhen the thing happened in the real world. Business numbers use it.
GrainWhat one row of a table means.
ETLExtract, transform, load. It transforms the data and then loads only the result.
The five stagesIngest, store, transform, serve, observe.
Load timeWhen the pipeline copied the row. It is not when the thing happened.
LatencyThe time from a change in the source until the warehouse can show it. Here: up to one day.
BatchOne run handles a whole slice of data, then stops. Its opposites are micro-batch and streaming.
FreshnessHow new the data in the warehouse is. Ask how fresh the result must be.
Micro-batch and streamingBatch with a very small slice, run again and again. And a job that never stops.

Each word has an interview line in the project's glossary.

6 · What is still wrong

The load grows until the API refuses it

The API allows calls in 10 seconds. A full load needs one more call every day or two. On Tuesday only of orders were new or changed, and it read them all anyway.

Still wrongIt reloads every order every day. It is slow, and it hits the API's rate limit.
Next: milestone 2, load only what changed. Keep a watermark: the latest updated_at already loaded. Each run asks the API only for orders changed since then.

Set up

What this milestone needs

Git, Python 3.12 or later, and uv. No Docker, no API key, no cloud account. Everything is free and runs on your computer.

Install uv: macOS and Linux

curl -LsSf https://astral.sh/uv/install.sh | sh

Install uv: Windows (PowerShell)

powershell -ExecutionPolicy ByPass -c "irm https://astral.sh/uv/install.ps1 | iex"

Then, on any system, from the project folder

uv sync                              # makes the virtual environment
uv run python -m order_system        # starts the order system; leave it running

In a second terminal:

uv run python -m order_system.clock --morning 2026-06-08
cd src/m1_report_by_hand
uv run python -m daily_orders        # prints the manager's report
uv run pytest                        # runs this milestone's tests

Every number on this page is written by daily_orders/flow_data.py from a real run of this milestone's code, and a test checks that they still match. All data is fictional. Arden does not exist.
