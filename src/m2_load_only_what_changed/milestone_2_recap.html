1 · What was asked

A report every morning, also on 11 June

Why this milestone exists. Milestone 1 read every order Arden ever took, every morning. The load grew by a call every day or two, until the order system refused it.

The business asked for four things: read only what changed, keep going when the order system is busy, keep everything that was sent, and know which run loaded each row.

3 · The idea underneath

Safe from loss means: expect repeats

Three choices in this milestone protect against losing a row. Each one can bring a row twice.

The filter includes the watermarkA row is never skippedSide effect: the boundary order is read again
A failed call is retriedA hiccup does not stop the reportSide effect: a page can arrive twice
Changed orders are loaded againA refund is never missedSide effect: the order arrives a second time

4 · What you learned

Five things

  1. Read only what changed, by a key that changes with the row.updated_at finds a refund. placed_at would miss it for ever.
  2. The watermark is the largest value you loaded, not the time the job ran.Two computers never agree exactly on the time.
  3. Save the watermark with the rows, in one transaction.Moved too early, a crash loses a whole morning and shows no error.
  4. Retry what a retry can fix, and cap the tries.Wait for a 429, back off after a 500, stop at once on a 400.
  5. Land raw first, exactly as received.A new question was answered from the warehouse, with no new call to the source.

5 · New words

Words you can now explain

Incremental loadIt reads only rows that are new or changed.
Incremental keyThe column that says a row changed. Pick one that changes whenever the row changes.
WatermarkThe saved value that marks how far the last run read. Also called a high-water mark.
PaginationAn API returns rows in pages. You ask again until it says it is done.
Rate limitA cap on how many calls you may make in a period.
Retry with backoffTry a failed call again, and wait longer each time. Always cap the tries.
Raw landing tableThe raw copy of what arrived.
Load metadataColumns about the load, not the data: which run, when.
AppendAdd rows at the end of a table. Never touch the rows already there.
Pull and pushWho starts the transfer: your job, or the source.
PollingAsking again and again: what is new?
Change data capture (CDC)Capturing each change to a table. A watermark load is query-based CDC.

Each word has an interview line in the project's glossary.

Set up

What is new to install: Docker

The warehouse is now Postgres, and it runs in Docker. Install Docker Desktop on macOS or Windows, or Docker Engine with the Compose plugin on Linux. Still no API key and no cloud account.

On any system, from the project folder

uv sync                              # installs the Postgres driver
docker compose up -d warehouse       # starts Postgres on port 5440
uv run python -m order_system        # starts the order system; leave it running

In a second terminal:

uv run python -m order_system.clock --morning 2026-06-08
cd src/m2_load_only_what_changed
uv run python -m daily_orders        # the first load: everything
uv run python -m order_system.clock --advance-days 1
uv run python -m daily_orders        # the second load: only what changed
uv run pytest                        # this milestone's tests

To stop the warehouse: docker compose down. Add -v to delete its data too.
